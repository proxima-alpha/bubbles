TDD — 구현 코드 작성 전 테스트를 먼저 작성하고, 이후 실행하여 통과를 확인한다.

## spec 대상 지정

- `plan` → `plan.md`
- `001` / `spec-001` / `1` → `specs/spec-001.md` 전체
- `001/1` / `spec-001-001` / `001-001` → spec-001의 태스크 (1)
  - `specs/spec-001-001.md` 이 있으면 해당 파일 사용
  - 없으면 `specs/spec-001.md` 의 태스크 (1) 항목만 대상
- 인수 없음 → 현재 진행 중인 spec 대상

## 실행 순서

1. **테스트 작성 (🔴 Red)** — spec을 읽고, 구현 코드 없이 테스트 파일만 작성
   - NestJS: `*.spec.ts` (Jest)
   - Next.js: `*.test.tsx` (Jest + React Testing Library), 단 UI 컴포넌트는 필요 시에만
   - 테스트 단위: 서비스 메서드 / API 엔드포인트 동작 / 주요 유틸 함수
   - 한 번에 하나씩 — 모든 케이스를 한꺼번에 쓰지 말 것

2. **테스트 실행** — 실패하는지 확인. 통과하면 테스트가 잘못된 것

3. **구현 (🟢 Green)** — 테스트를 통과하는 최소한의 코드 작성 (`/apply`와 동일한 규칙 적용)

4. **테스트 재실행** — 전체 통과 확인

5. **정리 (♻️ Refactor)** — 동작을 바꾸지 않는 선에서 코드 정리. 테스트 다시 통과 확인

## 테스트 작성 원칙

- 테스트명은 `~해야 한다` 형식으로 동작을 서술 (예: `"메모리를 저장하면 id가 반환되어야 한다"`)
- 외부 의존성(DB, LLM API)은 mock 처리
- 한 테스트는 한 가지만 검증
- 워크플로우 5단계(검증)에 해당 — `/apply` 직후 호출하는 것이 원칙
