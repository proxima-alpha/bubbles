확정된 plan을 기반으로 코드를 작성한다.

## spec 대상 지정

- `plan` → `plan.md`
- `001` → `specs/001/spec.md` 전체
- `001/1`, `001/task/1`, `001/task-001` → spec-001의 태스크 (1)
  - `specs/001/task-001.md` 가 있으면 해당 파일 사용
  - 없으면 `specs/001/spec.md` 의 태스크 (1) 항목만 대상
- `002/feed-001`, `002/feed/1` → `specs/002/feed-001.md`
- 인수 없음 → 아래 순서로 대상 결정:
  1. 가장 마지막 spec 폴더(`specs/NNN/`)에서 미완료 feed 파일 탐색
     — feed 파일 내 `- [ ]` 항목이 하나라도 있으면 미완료로 판단
     — 미완료 feed 파일이 있으면 그 파일을 대상으로 실행
  2. 미완료 feed 파일이 없고 대화 컨텍스트에 구현할 내용이 있으면
     다음 번호의 feed 파일(`feed-NNN.md`)을 새로 생성하고 해당 파일을 대상으로 진행
  3. 둘 다 해당 없으면 현재 진행 중인 spec.md 대상

## 완료 표시 규칙

- feed 파일 내 각 구현 항목은 `- [ ]` 체크박스로 관리
- 해당 태스크 완료 시 `- [x]`로 변경 (apply 실행 중 태스크 완료 때마다 업데이트)

## 실행 규칙

- 실행 전 반영되지 않은 주석 `[//]: # (...)` 이 남아있으면 먼저 `/feedback` 실행 후 진행
- 워크플로우 4단계(코드 작성)에 해당 — 유저의 명시적 호출 없이 단독 실행 금지
- 코드 작성 시작 전 대상 spec의 태스크 목록으로 TaskCreate 생성, 각 완료 시 TaskUpdate로 completed 처리
- 다중 태스크 실행 시 태스크별로 커밋. 커밋 메시지 형식: `<Keyword>: spec-NNN (N) <설명>`
- **push는 하지 않는다** — push는 `/confirm` 호출 시에만
